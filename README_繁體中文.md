# Riftforge — 獨立原創 Godot ARPG：可玩戰鬥試驗場

## 這是什麼

這是全新的 Godot 4.3+ **原創單機專案**。它是「角色操作 → 荒野刷怪 → 首領 → 地面掉寶 → 回營地換裝 → 再刷」的可玩 vertical slice，並非 Grim Dawn / POE 遊戲檔案轉換版，也不是完整商業遊戲。

使用者提供了 `database.rar`，其資料稽核報告顯示：`records/skills`、`records/items`、`records/creatures`、`records/controllers` 和 `records/game/combatformulas.dbr` 等資料具有分開建模的特徵。因此本專案採用獨立的**戰鬥數學、寶石圖、物品生成、敵人 AI、HUD、存檔**架構，而不是把遊戲資料全部塞進一支程式。只借鑑抽象的資料分層與類型；**不含、也不匯入 Grim Dawn / POE 的原始數據、名稱、貼圖、模型、音訊、腳本或引擎程式碼**。所有數值、名稱和系統程式均為本原型自製，**不能宣稱戰鬥公式與原遊戲相同**。

## 開啟方式（Windows）

1. 將 ZIP 完整解壓縮至新資料夾；**不要覆蓋任何既有 Riftforged 或 Grim Dawn 專案**。
2. 使用 Godot 4.3 或更新的 Godot 4.x（建議 Standard 版）開啟 `project.godot`。
3. 等待 Godot 初次匯入完成，在編輯器按 `F6` 執行主場景或按 `F5` 執行專案。
4. 角色在營地出生，走到藍色傳送門旁按 E；進入荒野後即可戰鬥。

不需要 `database.rar` 就可遊玩，因為不依賴遊戲專有資料。

## 操作

| 按鍵 | 功能 |
|---|---|
| `WASD` | 3D 斜俯視移動 |
| 滑鼠位置 | 瞄準方向 |
| 按住滑鼠左鍵 | 高速發射燼焰彈（含暴擊判定） |
| 滑鼠右鍵 | 震盪環 AoE，耗魔 25，有冷卻 |
| `Space` | 短衝刺（短暫無敵，有冷卻） |
| `E` | 靠近拾取地面戰利品／進入、離開傳送門 |
| `I` | 開啟背包、選擇裝備；武器加傷害，護甲加生命和減傷 |
| `G` | 開啟 3 孔連線寶石面板、安裝／卸下兩種輔助 |
| `Esc` | 關閉面板 |

寶石系統會真的影響投射物：分裂從 1 發變為 3 發、每發傷害降低；穿透能讓子彈多命中一個目標。兩個輔助須與主動寶石在連線圖中連通且標籤相容。設計參見 `scripts/gem_rules.gd`。

## 本次實際包含

- 營地與單張荒野、來回傳送門、死亡重生。
- 程式生成的原創幾何場景及臨時角色／怪物外形（僅佔位、便於日後替換自製 glTF 模型）。
- 3 種具有差異行為的敵人：追擊近戰、保持距離遠程、慢速重擊；進度達標後刷出首領。
- 攻擊前紅色地面預警、基本閃避、畫面震動、擊退、傷害浮字、爆發特效。
- 傷害／暴擊／抗性／護甲的**原創簡化公式**，可獨立測試。
- 一個主動技能、兩個有作用的輔助寶石、一個主動範圍技。
- 帶前後綴的原創隨機武器和護甲、地面掉落與互動拾取、背包裝備。
- JSON 保存背包、裝備、寶石、等級與累計進度，使用 Godot `user://`，不會修改原遊戲。

## 測試

```bash
godot --headless --path . --script res://tests/test_combat.gd
```

預期輸出 `TEST RESULT: 8 passed / 0 failed`。另請在 Godot 按 F5 做實際畫面、滑鼠、碰撞、回營及存檔驗收。若你的系統執行檔稱作 `Godot_v4...exe`，以該執行檔代替上面的 `godot` 即可。

## 結構

```text
project.godot
scenes/main.tscn
scripts/game.gd         世界、場景流程、掉落、施法、存檔
scripts/player.gd       角色移動、閃避、受傷
scripts/enemy.gd        追擊、遠程、重擊與 Boss AI
scripts/projectile.gd   投射物命中與穿透
scripts/hud.gd          UI、背包、寶石面板
scripts/loot.gd         地面物品
scripts/items.gd        自有物品基底／詞綴／生成
scripts/gem_rules.gd    連線／標籤與輔助判定
scripts/combat_math.gd  自有傷害／護甲計算
tests/test_combat.gd    可重複執行的遊戲數學測試
```

## 下一個 BUILD 的必要工作

1. 先以實機確認移動／施放／命中／閃避的手感，調整攻速、移速、攻擊距離和後搖；不能以「能射出子彈」代替手感驗收。
2. 加入你們自己的角色與怪物 glTF 模型、AnimationTree、攻擊命中影格、原創音效和真正可見的擊中停頓，替換暫用幾何體。
3. 擴充標籤化技能效果（彈跳、範圍、狀態等），加入裝備自由孔洞與可調連線，並保留自動化測試。
4. 多人同步、手機控制等獨立排程，不承諾目前就具備。
